⏺ I assume "patches" means "batches" (BATCH_SIZE). If you meant image patches,
  tell me.

  1. Why do we read the config with resolve_data_config?
  - Each pretrained model learned from images with one fixed color scale. The
    model needs the same scale at prediction time.
  - The mean and std are part of the model's training setup, so the model
    carries them. You asked for the values to come from the model, and this call
    does that.
  - The call is the standard way in timm, and the timm docs show it. The same
    call also returns the input size and the resize rule. We ignore those two,
    because you asked for no resize and no crop.
  - The values here are the ImageNet ones. Many models use the same values, but
    not all do. The call removes the need to know which model uses which values.

  2. What is to_normalized_tensor?
  It is a chain of two steps. It is a name I chose, not a library term.
  1. ToTensor converts the image to numbers. Pixel values 0 to 255 become
     decimals from 0 to 1. The order of axes changes from height, width, color
     to color, height, width.
  2. Normalize does (value - mean) / std for each color channel. The values then
     centre near 0, as they did during training.

  3. What is a tensor?
  - A tensor is a block of numbers with a fixed shape. It is the torch version
    of a numpy array.
  - One image here has shape (3, 375, 450): 3 colors, 375 rows, 450 columns.
  - A batch of 32 images has shape (32, 3, 375, 450).
  - A tensor can live on the GPU. A numpy array cannot. This is the main
    difference.

  4. Why do we use batches?
  - Speed is part of the reason. The GPU has many small workers. One image does
    not use all of them, so 32 images in one call use the GPU better. They also
    cost fewer calls.
  - Memory is the limit. The model must hold the numbers for every image in the
    batch at one time. A batch that is too large crashes the Mac GPU memory.
  - 32 is a safe size. If the run fails with a memory error, lower BATCH_SIZE.
  - The batch size does not change the result. Each image gets the same
    embedding in any batch.

  5. Why torch.inference_mode?
  - During training, torch records every step, so it can compute gradients
    later. The record uses memory and time.
  - We do not train, so we do not need the record. inference_mode switches it
    off.
  - The result is the same, but the run uses less memory and runs faster.
  - .eval() on the model is a different thing. It sets layers such as dropout to
    their prediction behavior. We need both.

  6. What is tqdm?
  - It is a small library that shows a progress bar for a loop. It shows how
    many steps are done, the speed, and the time that remains.
  - It has no effect on the result. We use it because the full run takes a long
    time, and the bar shows that the run is not stuck.

  What the cells do
  1. The first cell has name_label_combination, copied from notebook 01. It
     names the combination of each photo. It also loads train.npy.
  2. find_nearest_neighbor_indices normalizes each embedding to length 1. The

     gives the nearest photo.

     count. It shows the count and the percent of photos whose nearest photo
     has the same combination.
