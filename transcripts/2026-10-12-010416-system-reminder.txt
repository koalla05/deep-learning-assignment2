⏺ 1. .itertuples(index=False)

  train[label_columns] is a table with 5 label columns: Cat, Dog, Moris, Motya
  and Biatrix. itertuples goes through this table one row at a time. Each row
  comes out as a tuple, for example (1, 0, 1, 0, 0).

  name_label_combination needs exactly this tuple. It pairs each label name with
  its value, and it keeps the names with value 1. For that row the result is
  "Cat + Moris".

  index=False removes the row number from the tuple. Without it, the tuple would
  be (0, 1, 0, 1, 0, 0). The row number would shift every value by one
  position. The names would then pair with the wrong values.

  The groupby in the old code gives the same kind of tuple for each group. So
  one function serves both places.

  2. Why pd.DataFrame({...}) works

  Your idea is almost right. The word is "same order", not "sorted". No list is
  sorted. Every list follows the row order of train:

  - groups has one item for each row of train, in row order.
  - sizes has one item for each image_id of train, in row order.
  - train["image_id"] is a column of train, so it has the same order too.

  The data frame joins the columns by position. Item 0 of each list is row 0,
  item 1 is row 1, and so on. All columns have the same length, so each row gets
  the right values.

  The risk is a change of order. Do not sort or filter one list alone, because
  the rows would then pair with the wrong values.

  3. summarize_group_sizes

  This is the plan:

  1. image_sizes.groupby("group") splits the table into 8 smaller tables. Each
     one holds the images of one group.
  2. .apply(summarize) calls the inner function summarize one time for each
     small table. The function returns one row of results.
  3. .sort_values("images", ascending=False) puts the biggest group first.

  The inner function summarize handles one group. Take "Cat + Motya" as an
  example. It has 32 images. These are the steps:

  1. group.groupby(["width", "height"]).size() counts the images for each size
     pair. For example, 450×375 gives 30, and 500×333 gives 2.
  2. .sort_values(ascending=False) puts the pair with the highest count first.
  3. / len(group) divides each count by 32. The counts then become shares: 0.94
     and 0.06.
  4. size_shares.index[0] is the first pair, the most common size. We unpack it
     into top_width and top_height.
  5. size_shares.iloc[0] is the first share, the share of that most common size.
  6. pd.Series({...}) puts the 5 results in one row: image count, median width,
     median height, top size and top share.

  The groupby joins the 8 rows into the final table.

  Note the "most common width times height combination". I read it as the pair
  (width, height). I did not read it as the area (width × height). Tell me if
  you want the area, and I will change it.
